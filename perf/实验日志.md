# 性能实验日志

## 实验 1：停止自动加载音频 metadata

- 假设：把播放器的 `preload` 从 `metadata` 改为 `none`，会把首页用户操作前的音频请求从 1 降到 0，并避免最多 4,209,569 bytes 的非必要媒体请求。
- 做法：侧栏与音乐页播放器均使用 `preload="none"`。
- 护栏：播放按钮仍需在浏览器冒烟测试中成功触发播放；Bilibili 媒体继续保留 `referrerpolicy="no-referrer"`。
- 结果：保留。冷浏览器会话等待 2 秒后音频请求为 0，`audio.preload` 为 `none`；点击播放后 `paused === false` 且 `currentSrc` 指向预期音频。

## 实验 2：推迟侧栏播放器水合

- 假设：播放器并非首页“能用”的必要条件，将水合从 `client:load` 改为 `client:idle` 可减少加载关键阶段的主线程竞争，同时保留服务端渲染内容。
- 做法：仅调整侧栏播放器的 Astro client directive。
- 护栏：首页播放器可见、空闲后播放按钮可交互。
- 结果：保留。首页服务端内容与播放器均正常显示，空闲后播放按钮可交互；无错误遮罩。

## 实验 3：构建期重编码固定背景

- 假设：将首屏固定背景从 JPEG 重编码为同尺寸 WebP，可以在不改变布局的前提下降低图片字节数和下载耗时。
- 做法：`bg.jpg` 以 WebP quality 82、method 6 重编码；页面背景引用改为 `bg.webp`。原 JPEG 保留给 Open Graph，避免改变分享元数据。
- 确定性计数：页面背景从 229,486 bytes 降到 89,932 bytes，减少 139,554 bytes（60.8%）。
- 护栏：桌面视口截图回归、资源请求检查、构建和性能预算。
- 结果：保留。浏览器请求 `/bg.webp`，优化前后桌面截图像素差为 0%，构建和性能预算通过。

## 实验 4：构建期重编码头像

- 假设：将首页首屏头像从 JPEG 重编码为同尺寸 WebP，可以进一步减少图片字节数且不改变布局。
- 做法：`avatar.jpg` 以 WebP quality 82、method 6 重编码，配置引用改为 `avatar.webp`。
- 确定性计数：头像从 30,624 bytes 降到 4,680 bytes，减少 25,944 bytes（84.7%）。
- 护栏：截图像素回归、资源请求检查、构建和性能预算。
- 结果：保留。浏览器仅请求 `/avatar.webp`，优化前后首页截图像素差为 0%，构建和性能预算通过。

## 实验 5：让 Swup 按页面更新 head

- 假设：首页当前加载 12 个样式表、共 283,407 bytes，其中包含仅评论页或文件页使用的 `WalineComments`、`FileBrowser` CSS。启用 Swup 官方默认的 `updateHead` 后，可按路由维护样式和元数据，并从首页关键路径移除无关 CSS。
- 做法：将 `updateHead` 从 `false` 改为 `true`；保持 Swup 缓存、预加载和动画不变。
- 护栏：首页视觉截图、首页到关于页的 Swup 导航、title/canonical 更新、返回首页、构建和资源计数。
- 结果：回退。构建后首页仍为 12 个样式表、283,407 bytes，确定性指标没有改善，不承担导航行为变化的风险。

## 实验 6：消除重复的 Tailwind 引用入口

- 假设：当前 `tailwind-reference.css` 同时被全局 `@import` 和多个文件 `@reference`，构建后形成 90,957-byte `global.css` 与 62,865-byte `tailwind-reference.css` 两个含重复工具类的产物。直接引用 `tailwindcss` 包可保留 `@apply` 的主题上下文，并避免把辅助入口作为额外样式表输出。
- 做法：全局入口改为 `@import "tailwindcss"`，五个使用 `@apply` 的样式文件改为 `@reference "tailwindcss"`；暂不删除原辅助文件，便于回退。
- 护栏：首页 CSS 请求数/字节数、构建、桌面截图像素差、首页与文章页冒烟。
- 结果：保留。删除已无引用的旧辅助入口后，首页 CSS 从 12 个 / 283,407 bytes 降至 11 个 / 192,682 bytes，减少 90,725 bytes（32.0%）。亮色首页截图像素差为 0%；暗色主题和文章页均通过浏览器冒烟测试。

## 实验 7：裁剪静态发布冗余

- 假设：KaTeX 字体已声明 WOFF2 优先，移除仅用于旧浏览器回退的 WOFF/TTF 不影响现代 Chromium；未引用的旧头像 JPEG 可直接移除；Open Graph 原始背景可替换为社交卡片标准尺寸的专用 JPEG。
- 做法：KaTeX CSS 只保留 WOFF2 源，移除 20 个 WOFF 和 20 个 TTF；删除未引用的 `avatar.jpg`；把 `bg.jpg` 生成 1200×630、quality 80 的 `og.jpg` 并更新 OG 元数据，然后移除原图。
- 预计确定性收益：KaTeX 减少 816,780 bytes；头像减少 30,624 bytes；OG 图减少 140,980 bytes，合计 988,384 bytes。
- 护栏：构建、全站引用扫描、OG 标签尺寸与 MIME、数学页字体请求、首页/文章/音乐页冒烟。
- 结果：保留。实验后 `dist` 为 11,967,448 bytes；KaTeX 仅剩 20 个 WOFF2（259,792 bytes），数学字体在浏览器中加载成功；OG 标签为 JPEG、1200×630；旧头像和背景无残留引用。

## 实验 8：外置并复用页面样式

- 假设：当前 24 个 HTML 合计 2,126,937 bytes，多个路由重复内联相同组件样式。强制 Astro 不内联样式可让 CSS 按内容寻址复用，减少 `dist` 总大小和 HTML 解析量。
- 做法：设置 `build.inlineStylesheets: "never"`。
- 基线：实验 7 后 `dist` 为 11,967,448 bytes，首页 HTML 为 95,292 bytes。
- 护栏：总产物、首页 HTML、首页 CSS 请求/字节、亮暗色视觉、跨页导航和构建。
- 结果：回退。`dist` 降到 11,364,529 bytes（减少 602,919），但首页 CSS 从 11 个 / 192,682 bytes 增到 27 个 / 219,807 bytes。为避免增加 16 个渲染阻塞请求，不保留该方案。

## 实验 9：裁剪 Pagefind 可选 UI

- 假设：本站只动态导入 Pagefind 核心 API，自定义搜索 UI 未引用 Pagefind 自带的 component/ui/modular/highlight 文件；构建后删除它们不会影响搜索。
- 做法：增加确定性构建后脚本，精确删除 7 个未引用的可选资源。
- 预计收益：418,109 bytes。
- 护栏：实际搜索输入并打开结果、核心 worker/WASM/索引存在、构建和产物预算。
- 结果：保留。构建脚本实际移除 418,109 bytes；浏览器搜索“服务”正常返回两个结果，核心 JS、worker、WASM 和索引均可用。

## 实验 10：按语言子集发布 Roboto

- 假设：当前 Roboto 发布 48 个 WOFF/WOFF2 文件、656,144 bytes。站点的拉丁系界面只需要 Latin、Latin Extended、Vietnamese，且现代目标浏览器支持 WOFF2。
- 做法：用一份显式字体 CSS 仅引入 400/500/700 三个字重的三个所需 WOFF2 子集；中日韩继续使用原有系统字体回退。
- 预计收益：约 519,100 bytes。
- 护栏：中英文与越南语界面、字体加载请求、首页截图和构建。
- 结果：保留。Roboto 从 48 个 / 656,144 bytes 降至 9 个 / 137,044 bytes，减少 519,100 bytes；首页截图像素差 0%，越南语切换与所需子集请求正常。
